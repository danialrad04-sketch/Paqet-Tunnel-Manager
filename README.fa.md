# Paqet-Tunnel-Manager

اسکریپت مدیریتی برای **paqet**: یک تونل مبتنی بر Raw Socket و KCP که برای عبور از فایروال و DPI طراحی شده است. این اسکریپت از سناریوی **سرور خارج (Kharej)** و **کلاینت ایران (Entry Point)** پشتیبانی می‌کند.

توضیحات آپدیت ها فقط در تلگرام داده میشود.

## مراحل نصب

### مرحله ۱: راه‌اندازی سرور خارج (Kharej – VPN Server)

اسکریپت را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/behzadea12/Paqet-Tunnel-Manager/main/paqet-manager.sh)
```

#### مراحل پیکربندی

1. **گزینه 2** را انتخاب کنید (Kharej)
2. **یک نام دلخواه** برای سرویس/تونل وارد کنید (مثال: `fanland1`)
3. **پورت Listen** را وارد کنید (مثال: `443` یا `8443`)
4. برای ساخت خودکار **Secret Key**، **Enter** بزنید
5. **کلید ساخته‌شده را ذخیره کنید** سپس **`Y`** را برای تأیید بزنید
6. **حالت KCP** را انتخاب کنید (پیشنهادی: گزینه `1` - fast)
7. **conn value** → تعداد اتصال‌های KCP (مثال: `4`)
8. **MTU** → مقدار پیش‌فرض `1350` (در صورت نیاز می‌توانید مثلاً `1200` وارد کنید)
9. **متد Encryption** را انتخاب کنید (پیش‌فرض: `aes-128-gcm`)
10. **pcap sockbuf** → برای مقدار پیش‌فرض **Enter** بزنید
11. **transport tcpbuf** → برای مقدار پیش‌فرض **Enter** بزنید
12. **transport udpbuf** → برای مقدار پیش‌فرض **Enter** بزنید

---

### مرحله ۲: راه‌اندازی سرور ایران (Iran – Client/Entry Point)

اسکریپت را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/behzadea12/Paqet-Tunnel-Manager/main/paqet-manager.sh)
```
#### مراحل پیکربندی

1. **گزینه 3** را انتخاب کنید (Iran)
2. **یک نام دلخواه** برای سرویس/تونل وارد کنید (مثال: `fanland`)
3. **آی‌پی سرور خارج** را وارد کنید (مثال: `65.109.206.29`)
4. **پورت سرور** (پورت ارتباطی بین دو سرور) را وارد کنید (مثال: `443`)
5. **کلید سکرت** که روی سرور خارج ساخته شده را وارد کنید
6. **حالت KCP** را انتخاب کنید (پیشنهادی: گزینه `1` - fast)
7. **conn value** → تعداد اتصال‌های KCP (پیش‌فرض: `1`)
8. **MTU** → مقدار پیش‌فرض `1350` (Enter بزن)
9. **متد Encryption** را انتخاب کنید (پیش‌فرض: `aes-128-gcm`)
10. **pcap sockbuf** → برای مقدار پیش‌فرض **Enter** بزنید
11. **transport tcpbuf** → برای مقدار پیش‌فرض **Enter** بزنید
12. **transport udpbuf** → برای مقدار پیش‌فرض **Enter** بزنید
13. **پورت یا پورت‌های Forward** را وارد کنید
    تک پورت: `333` — چند پورت: `333,394,395`
14. **برای هر پورت، پروتکل را انتخاب کنید**
    `1` tcp — `2` udp — `3` tcp/udp

## تنظیمات پیشرفته (حالت‌های KCP)

در **مرحله 8 (سرور خارج)** و **مرحله 9 (سرور ایران)** می‌توانید حالت‌های مختلف KCP را انتخاب کنید.

### حالت‌های KCP

0. **normal** – سرعت نرمال، تأخیر نرمال، مصرف منابع کم
1. **fast** – سرعت متعادل، تأخیر کم، مصرف منابع نرمال
2. **fast2** – سرعت بالا، تأخیر کمتر، مصرف منابع متوسط
3. **fast3** – حداکثر سرعت، تأخیر بسیار کم، مصرف CPU بالا
4. **manual** – تنظیمات پیشرفته به‌صورت دستی

> **پیشنهاد:**
> طبق بازخورد کاربرانی که از این اسکریپت استفاده کرده‌اند، **گزینه 1 (fast)** در اکثر شرایط بهترین عملکرد را دارد.
> اگر **سرور ایران شما محدودیت شبکه یا منابع** دارد، پیشنهاد می‌شود حالت‌های مختلف را تست کنید.
> در صورتی که **دانش فنی و تجربه کافی** دارید، می‌توانید از **manual** برای تنظیم دقیق همه پارامترها استفاده کنید.

## بهینه‌سازی شبکه (اختیاری)

اسکریپت را اجرا کنید:

```bash

```

سپس **گزینه 7** را انتخاب کرده و یکی از موارد زیر را انتخاب کنید:

## عیب‌یابی: مشکلات نصب Paqet

اگر در هنگام پیکربندی، نصب Paqet به‌صورت خودکار انجام نشد
(مثلاً پیام **"Failed to install Paqet"** نمایش داده شد یا اسکریپت هنگام افزودن کانفیگ در حالت **Kharej** یا **Iran** متوقف شد)، مراحل زیر را انجام دهید:

---

### 1. دانلود دستی فایل Paqet

به صفحه ریلیز رسمی مراجعه کنید:
[https://github.com/hanselime/paqet/releases](https://github.com/hanselime/paqet/releases)

* **آخرین نسخه** را دانلود کنید.
* فایل متناسب با معماری سرور خود را انتخاب کنید:

  * `paqet-linux-amd64-*.tar.gz` → برای سرورهای 64 بیتی (x86_64 / amd64)
  * `paqet-linux-arm64-*.tar.gz` → برای سرورهای ARM (aarch64 / arm64)

### 2. قرار دادن فایل در مسیر مشخص‌شده

فایل دانلودشده را در مسیر زیر قرار دهید:

```bash
/root/paqet/
```

اگر این پوشه وجود ندارد، ابتدا آن را بسازید:

```bash
mkdir -p /root/paqet
```

### 3. اجرای مجدد اسکریپت

اسکریپت به‌صورت خودکار فایل موجود در `/root/paqet/` را شناسایی کرده، استخراج می‌کند و نصب را کامل می‌کند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/behzadea12/Paqet-Tunnel-Manager/main/paqet-manager.sh)
```

---

### 4. خطای GLIBC_2.32 یا GLIBC_2.34 not found

اگر سرویس با خطایی مشابه زیر متوقف شد:

```
/usr/local/bin/paqet: version `GLIBC_2.34' not found
```

یعنی نسخه glibc سیستم شما قدیمی‌تر از نسخه موردنیاز باینری Paqet است
(مثلاً Ubuntu 18.04 یا Debian 10).

#### راه‌حل اول: ارتقای سیستم‌عامل

سیستم‌عامل را به توزیعی با glibc 2.34+ ارتقا دهید:

* Ubuntu 22.04 یا جدیدتر
* Debian 12 یا جدیدتر

سپس دوباره Paqet را با منیجر (گزینه 0) نصب کنید.

#### راه‌حل دوم: کامپایل از سورس روی همان سرور

برای اینکه Paqet با glibc فعلی سیستم شما لینک شود:

```bash
apt install -y golang git
git clone https://github.com/hanselime/paqet.git && cd paqet
go build -o paqet ./cmd/paqet
sudo cp paqet /usr/local/bin/paqet
sudo chmod +x /usr/local/bin/paqet
```

سپس سرویس Paqet را دوباره استارت کنید:

List Services → Manage → Start

#### راه‌حل سوم: استفاده از VPS جدیدتر

از یک VPS با توزیع جدیدتر (مثلاً Ubuntu 22.04) استفاده کرده و Paqet را روی آن نصب کنید.

---

### 5. خطای bind: address already in use (پورت در حال استفاده است)

اگر Paqet با خطایی مشابه زیر متوقف شد:

```
failed to bind TCP socket on 0.0.0.0:8443: bind: address already in use
```

یعنی آن پورت (مثلاً 8443) روی همان سرور قبلاً توسط برنامهٔ دیگری استفاده می‌شود، یا همان پورت دو بار در لیست forward وارد شده است.

#### بررسی استفاده از پورت

```bash
ss -tuln | grep 8443
```

یا

```bash
lsof -i :8443
```

اگر سرویس دیگری (مثلاً nginx، وب‌سرور، یا V2Ray) روی آن پورت فعال است، یا آن سرویس را متوقف کنید یا در کانفیگ Paqet پورت دیگری انتخاب کنید.

#### حذف پورت تکراری

اگر پورتی دو بار در لیست پورت‌ها وارد شده است:

* فایل کانفیگ را ویرایش کنید:

```bash
nano /etc/paqet/نام_کانفیگ.yaml
```

* در بخش `forward:`، هر خطی که همان پورت را دوباره `listen` می‌کند حذف کنید.
* سپس سرویس را ریستارت کنید:

```bash
systemctl restart paqet-نام_کانفیگ
```

در نسخه‌های جدید اسکریپت، پورت‌های تکراری به‌صورت خودکار حذف می‌شوند.

## پنل وب Paqet

نصب‌کنندهٔ عمومی از شاخهٔ main نصب می‌کند و در اجرای بدون آرگومان دسترسی HTTP با IP را فعال می‌کند. برای دسترسی محلی، `--local-http` بدهید. بعد از ورود، «راهنمای اتصال» روی داشبورد مراحل دو میزبان را نشان می‌دهد. در جزئیات کلاینت، آزمون TLS پاسخ برنامه را از یک ورودی TCP ثبت‌شده بررسی می‌کند. در حالت تکرار، آزمون هر ۳۰ ثانیه در زمان باز و قابل‌مشاهده بودن جزئیات اجرا می‌شود.

پنل فارسی روی Debian/Ubuntu و systemd اجرا می‌شود. تونل‌های نصب‌شده با اسکریپت ترمینال را از سرویس‌های `paqet-*.service` می‌خواند و از قالب تنظیمات `/etc/paqet/<name>.yaml` استفاده می‌کند.

### اتصال دو میزبان

در جزئیات تونل سرور خارج، «دریافت فایل اتصال کلاینت» را بزنید. این JSON شامل کلید مشترک است. در پنل ایران، نقش کلاینت را انتخاب و فایل را وارد کنید. IPv4 عمومی میزبان خارج را در فیلد سرور مقصد وارد کنید. برای مثال اگر کاربران باید به پورت ۸۴۴۳ ایران وصل شوند و برنامهٔ مقصد روی پورت ۴۴۳ خود سرور خارج است، ورودی را `0.0.0.0:8443` و مقصد انتقال را `127.0.0.1:443` بگذارید. پورت ارتباط Paqet از فایل اتصال خوانده می‌شود.

در جزئیات کلاینت می‌توانید قوانین انتقال موجود را ویرایش کنید. «ویرایش کامل YAML» فیلدهای تنظیمات هسته از جمله شبکه، SOCKS5، رمزنگاری، KCP دستی، FEC و بافرها را در اختیار شما می‌گذارد. در «ساخت از YAML» می‌توانید متن تنظیمات اصلی را وارد کنید. ویرایش پورت سرورهای قدیمی ساخته‌شده با اسکریپت ترمینال ممکن است به تغییر قواعد فایروال همان میزبان نیاز داشته باشد.

### نصب

روی سرور Debian یا Ubuntu، این دستور آخرین فایل‌های شاخهٔ `main` را از GitHub دریافت می‌کند. اگر هسته موجود نباشد، نسخهٔ رسمی `v1.0.0-alpha.21` متناسب با amd64 یا arm64 را با بررسی SHA-256 نصب می‌کند.

```bash
curl -fsSL https://raw.githubusercontent.com/danialrad04-sketch/Paqet-Tunnel-Manager/main/bootstrap-web.sh -o bootstrap-web.sh && sudo bash bootstrap-web.sh
```

اگر `curl` نصب نیست، ابتدا `sudo apt-get update && sudo apt-get install -y curl ca-certificates` را اجرا کنید. اگر مخزن را از قبل دانلود کرده‌اید، می‌توانید از پوشهٔ مخزن اجرا کنید:

```bash
sudo bash install-web.sh
```

برای استفاده از نسخهٔ دیگری از هسته، مسیر فایل یا لینک انتشار را به نصب‌کننده بدهید. فایل یا بایگانی لینوکسی متناسب با معماری میزبان و SHA-256 معتبر آن را انتخاب کنید:

```bash
sudo bash install-web.sh --core /path/to/paqet --sha256 SHA256
# یا دانلود مستقیم فایل تأییدشده
sudo bash install-web.sh --core-url 'https://RELEASE-ASSET-URL' --sha256 SHA256
```

نصب‌کننده وابستگی‌ها را نصب می‌کند و توکن را در `/etc/paqet-panel/token` می‌سازد. توکن را روی میزبان با `sudo cat /etc/paqet-panel/token` بخوانید. از کامپیوترتان مسیر SSH را باز کنید و سپس به [پنل محلی](http://127.0.0.1:8765) بروید:

```bash
ssh -N -L 8765:127.0.0.1:8765 USER@SERVER
```

اگر هم‌زمان به میزبان دوم متصل می‌شوید، برای سمت محلی آن از پورت دیگری مانند ۸۷۶۶ استفاده کنید. پنل روی loopback گوش می‌دهد و درخواست مرورگر را با توکن و نشست ۸ ساعته احراز هویت می‌کند.

### دسترسی مستقیم با IPv4

برای فعال کردن دسترسی مستقیم به `http://SERVER_IP:8765`، نصب‌کننده را با `--public-http` اجرا کنید:

```bash
sudo bash install-web.sh --public-http
```

اگر فایروال میزبان یا ارائه‌دهنده فعال است، ورودی TCP پورت ۸۷۶۵ را برای IP مدیریتی خودتان مجاز کنید. در HTTP توکن ورود و نشست رمزنگاری نمی‌شوند. برای بازگشت به دسترسی محلی از طریق SSH، همان دستور را با `--local-http` اجرا کنید.

### راه‌اندازی تونل

روی هر دو میزبان از نسخهٔ یکسان هسته استفاده کنید. در پنل میزبان اول یک تونل سرور بسازید و کلید نمایش‌داده‌شده را نگه دارید. در پنل میزبان دوم یک تونل کلاینت با IPv4 میزبان سرور، پورت تونل، همان کلید و پارامترهای KCP بسازید. کلاینت دست‌کم به یک قانون انتقال یا SOCKS5 محلی نیاز دارد. SOCKS5 به loopback کلاینت محدود است. در انتقال پورت، IP و پورت شنود کلاینت و IP و پورت مقصد از دید سرور جداگانه انتخاب می‌شوند.

پنل رابط شبکه، IPv4 محلی و MAC دروازه را از مسیر پیش‌فرض تشخیص می‌دهد. هر سرویس سرور جدید قوانین iptables مربوط به پورت خودش را هنگام شروع اضافه و در توقف حذف می‌کند. شمارنده‌های نمای کلی وضعیت سرویس در systemd را نشان می‌دهند. اتصال انتها‌به‌انتها را از سرویس مقصد بررسی کنید.

برای نصب چند تونل روی یک میزبان، در «راه‌اندازی گروهی» فایلی مانند نمونهٔ زیر بارگذاری کنید. ورودهای سرور می‌توانند کلید را برای تولید خودکار خالی بگذارند. در کلاینت، کلید باید با سرور مقصد یکسان باشد. خروجی هر مورد و کلیدهای سرور در همان پنجره نمایش داده می‌شود. موارد موفق بلافاصله فعال می‌شوند؛ برای اجرای دوباره فقط موارد ناموفق را اصلاح و ارسال کنید.

```json
[
  {"name":"edge-01","role":"server","port":443,"mode":"fast","conn":1,"mtu":1350},
  {"name":"edge-02","role":"server","port":8443}
]
```

نمونهٔ ورودی کلاینت:

```json
[
  {"name":"relay-01","role":"client","remote":"203.0.113.10","port":443,"key":"REPLACE-WITH-SERVER-KEY","forwards":[{"listen":8443,"target":443,"protocol":"both"}]}
]
```

از «جزئیات» هر تونل می‌توانید آن را شروع، متوقف یا راه‌اندازی مجدد کنید، اجرای خودکار در زمان بوت را تغییر دهید و خروجی آخر journal را ببینید. فرم KCP حالت، MTU و تعداد اتصال را تغییر می‌دهد. اگر راه‌اندازی مجدد پس از ویرایش موفق نباشد، پنل فایل قبلی را بازیابی می‌کند.

### پایش، کشف سرویس‌ها و بازیابی

داشبورد خطاهای systemd را بالای صفحه نمایش می‌دهد و پردازنده، حافظه و نرخ ترافیک رابط شبکه را هر ۱۰ ثانیه نمونه‌برداری می‌کند. ترافیک نمایش‌داده‌شده مجموع ترافیک رابط انتخابی است. در جدول، چند سرویس را انتخاب کنید تا عملیات شروع، توقف یا راه‌اندازی مجدد به‌صورت گروهی اجرا شود.

پنل مسیر تنظیمات سرویس از `ExecStart` را برای فایل‌های داخل `/etc/paqet` می‌خواند و فایل‌های YAML بدون سرویس را جداگانه نشان می‌دهد. نقش از فیلد `role` و در نبود آن از ساختار آدرس شنود یا مقصد تشخیص داده می‌شود. موقعیت جغرافیایی را از «میزبان» ثبت کنید. در فرم ساخت، ایران کلاینت و خارج سرور را پیشنهاد می‌دهد و انتخاب نقش قابل تغییر است.

در جزئیات کلاینت می‌توانید مسیر IPv4 مقصد را با رابط و IP ثبت‌شده مقایسه کنید. نتیجهٔ این بررسی فقط مسیر سیستم‌عامل را نشان می‌دهد. برای آزمون عبور ترافیک، سرویس مقصد را از طریق پورت فورواردشده بررسی کنید. قبل از هر ویرایش KCP، یک نقطهٔ بازیابی محلی در `/etc/paqet-panel/restore-points` ذخیره می‌شود. اگر پس از ویرایش فایل را خارج از پنل تغییر دهید، بازیابی از بازنویسی آن جلوگیری می‌کند.

مرجع طراحی گردش کار پایش و نگهداری، [مستندات پنل BackPack](https://github.com/AminMGMT/BackPack/blob/main/docs/web-panel-screens.md) است.

### حذف تونل و مدیریت سرورها

در جزئیات تونل، «حذف و انتقال به آرشیو» را باز کنید و نام دقیق تونل را وارد کنید. پنل سرویس را متوقف و اجرای خودکار آن را غیرفعال می‌کند. فایل تنظیمات و واحد systemd به‌صورت آرشیو محلی با مجوز خصوصی ذخیره می‌شوند. از «سرورها و آرشیو» می‌توانید سرویس را با وضعیت قبلی بازیابی کنید. حذف از پنل برای سرویس‌هایی در دسترس است که فایل تنظیمات مستقل و واحد استاندارد محلی دارند. قواعد فایروال مشترک یا قواعدی که مدیر ترمینال بیرون از واحد systemd ساخته است، با این عملیات دست‌کاری نمی‌شوند.

در جزئیات سرویس، «بازتشخیص و اعمال تنظیمات شبکه» رابط، IPv4 محلی و MAC گام بعدی را دوباره تعیین می‌کند. برای کلاینت مسیر تا مقصد و برای سرور مسیر پیش‌فرض بررسی می‌شود. این کار تنظیمات شبکهٔ همین تونل را تغییر می‌دهد و برای سرویس فعال راه‌اندازی مجدد انجام می‌دهد. نسخهٔ قبلی از همان بخش قابل بازیابی است.

بخش «میزبان» آدرس‌ها و MTU رابط‌ها، جدول مسیر اصلی، DNS، پورت‌های شنود TCP و UDP، مصرف دیسک و مدت روشن بودن سرور را نشان می‌دهد. دفتر سرورها آدرس پنل‌های دیگر را ذخیره می‌کند تا هر پنل را مستقیم در مرورگر باز کنید. توکن هر پنل را در همان پنل وارد کنید.

### پیش‌نمایش

با Python 3 و PyYAML، دستور زیر داده‌های نمونه را روی همان آدرس محلی ارائه می‌کند. این حالت عملیات سیستم را شبیه‌سازی می‌کند و دسترسی root لازم ندارد.

```bash
python3 web/panel.py --demo
```
